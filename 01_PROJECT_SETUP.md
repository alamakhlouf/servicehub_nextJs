# Project Setup — ServiceHub (Next.js + Tailwind + MongoDB + PWA)

## 1. Prerequisites
- Node.js LTS and npm
- Git
- MongoDB Community Server running locally, or a MongoDB Atlas connection
- MongoDB Compass (optional, useful for inspecting collections)

For local MongoDB, the URI is normally `mongodb://127.0.0.1:27017`. For Atlas, use the connection string supplied by Atlas. Do not mix the local URI format with the Atlas `mongodb+srv://` format.

## 2. Create the Next.js project
Run:
```bash
npx create-next-app@latest servicehub
cd servicehub
```
Choose:
- TypeScript: Yes
- ESLint: Yes
- Tailwind CSS: Yes
- `src/` directory: Yes
- App Router: Yes
- Import alias: `@/*`

Install runtime dependencies:
```bash
npm install mongodb bcryptjs jose zod
```
Optional icon package:
```bash
npm install lucide-react
```
Do not install a large component library unless the team agrees it is needed.

## 3. Environment variables
Create `.env.local` at the project root:
```env
MONGODB_URI=mongodb://127.0.0.1:27017
MONGODB_DB=servicehub
AUTH_SECRET=replace-with-a-long-random-secret
```
Generate a secret locally, for example with `openssl rand -base64 32`, or use a long random value generated by a password manager.

Create `.env.example` with placeholders only:
```env
MONGODB_URI=mongodb://127.0.0.1:27017
MONGODB_DB=servicehub
AUTH_SECRET=replace-me
```
Never commit `.env.local`, database passwords, or real secrets. Confirm `.env.local` is in `.gitignore`.

## 5. MongoDB connection helper
Create `src/lib/db/mongodb.ts`:
```ts
import { MongoClient } from "mongodb";

const uri = process.env.MONGODB_URI;
if (!uri) throw new Error("Missing MONGODB_URI");

const options = {};
let client: MongoClient;
let clientPromise: Promise<MongoClient>;

declare global {
  // eslint-disable-next-line no-var
  var _mongoClientPromise: Promise<MongoClient> | undefined;
}

if (process.env.NODE_ENV === "development") {
  if (!global._mongoClientPromise) {
    client = new MongoClient(uri, options);
    global._mongoClientPromise = client.connect();
  }
  clientPromise = global._mongoClientPromise;
} else {
  client = new MongoClient(uri, options);
  clientPromise = client.connect();
}

export default clientPromise;
```
Use this helper only in server code (Route Handlers, Server Components, server utilities). Never import it into a Client Component.

Example server-side collection access:
```ts
import clientPromise from "@/lib/db/mongodb";

const client = await clientPromise;
const db = client.db(process.env.MONGODB_DB ?? "servicehub");
const services = db.collection("services");
```

## 6. Design system setup
### Fonts
In `src/app/layout.tsx`, load Google fonts using `next/font/google`:
```tsx
import { Inter, Plus_Jakarta_Sans } from "next/font/google";
import "./globals.css";

const inter = Inter({ subsets: ["latin"], variable: "--font-inter" });
const jakarta = Plus_Jakarta_Sans({
  subsets: ["latin"],
  variable: "--font-jakarta",
});

export default function RootLayout({ children }: Readonly<{ children: React.ReactNode }>) {
  return (
    <html lang="en" className={`${inter.variable} ${jakarta.variable}`}>
      <body>{children}</body>
    </html>
  );
}
```
If the build environment cannot fetch Google fonts, use local/system fallbacks rather than blocking the build.

### Visual rules
- Primary actions: blue `#2563EB`.
- Success and secondary actions: green `#10B981`.
- Attention: amber `#F59E0B`, used sparingly.
- Base: deep navy `#0F172A` / darker page background.
- Use white/off-white text and slate-muted text.
- Use blue focus rings and visible keyboard focus.
- Buttons, cards, badges, fields, nav items must be shared components.
- Do not make every card brightly colored. Most surfaces should be neutral navy.
- Keep mobile navigation compact and desktop navigation persistent.
- Maintain readable contrast; do not use the palette colors as tiny text on similar backgrounds.

## 7. Shared components to build first
- `Button`: primary, secondary, outline, danger, disabled/loading.
- `Input`, `Textarea`, `Select`: labels, helper/error text, focus state.
- `Card`: standard surface, border, radius.
- `Badge`: status colors for pending/success/warning/error.
- `PageHeader`: title, description, primary action.
- `EmptyState`, `LoadingState`, `ErrorState`.
- `AppShell`: responsive header/sidebar/mobile navigation.
Keep component APIs small and consistent.

## 9. Shared service worker — register only once
Create `public/sw.js`:
```js
const CACHE_NAME = "servicehub-shell-v1";
const SHELL_URLS = ["/offline"];

self.addEventListener("install", (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME)
      .then((cache) => cache.addAll(SHELL_URLS))
      .then(() => self.skipWaiting())
  );
});

self.addEventListener("activate", (event) => {
  event.waitUntil(
    caches.keys()
      .then((keys) => Promise.all(
        keys.filter((key) => key.startsWith("servicehub-") && key !== CACHE_NAME)
          .map((key) => caches.delete(key))
      ))
      .then(() => self.clients.claim())
  );
});

self.addEventListener("fetch", (event) => {
  const request = event.request;
  const url = new URL(request.url);

  if (request.method !== "GET" || url.origin !== self.location.origin) return;

  // Never cache authenticated API responses by default.
  if (url.pathname.startsWith("/api/")) return;

  if (request.mode === "navigate") {
    event.respondWith(
      fetch(request).catch(async () =>
        (await caches.match(request)) ||
        (await caches.match("/offline")) ||
        Response.error()
      )
    );
  }
});
```
This is a safe starter worker. Each feature may add an explicitly reviewed cache strategy or message handler to this same file. Do not blindly cache all pages or private API responses.

Create `src/components/pwa/PwaRegister.tsx`:
```tsx
"use client";
import { useEffect } from "react";

export default function PwaRegister() {
  useEffect(() => {
    if ("serviceWorker" in navigator) {
      navigator.serviceWorker.register("/sw.js").catch(console.error);
    }
  }, []);
  return null;
}
```
Render `<PwaRegister />` once in the root layout. Do not register a worker in feature pages.

Create `src/app/offline/page.tsx` with a clear offline message and a link back to the home page.

## 10. Backend conventions
- Use Next.js Route Handlers under `src/app/api/.../route.ts`.
- Use `GET`, `POST`, `PATCH`, and `DELETE` according to the resource.
- Validate request bodies with Zod on the server.
- Authenticate and authorize every private operation.
- Derive `userId` and `role` from the verified session, never from request JSON.
- Check ownership before update/delete.
- Return JSON with useful status codes: 200, 201, 400, 401, 403, 404, 409, 500.
- Do not expose password hashes or secrets.
- Use `ObjectId.isValid()` before querying by ID.

## 11. Authentication implementation note
Use `bcryptjs` to hash passwords and `jose` to sign/verify a short-lived session token. Store the token in an `httpOnly`, `secure` (in production), `sameSite: "lax"` cookie. Implement server-side helpers such as `getCurrentUser()` and `requireRole()`. Do not store auth tokens in localStorage or IndexedDB. Keep this implementation centralized in `src/lib/auth/`.
